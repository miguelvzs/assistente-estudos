# Documentação da base SUAP
O commit que muda o código leva junto os documentos que ficariam falsos.
App/Resultado → EXPLICACAO, roteiro e DESIGN. Serviço/configuração → ARCHITECTURE,
INTEGRACAO-SUAP e README. Dependências/comandos → README e INVENTARIO. Validações
→ VALIDACAO. Mudança de escopo → ESCOPO e spec antes do código.

Não copiar fatos da main OpenAI como se fossem validação SUAP. Não documentar
rotas, permissões ou formatos da instituição sem evidência. Commits unitários
seguem COMMITS.md; sem trailer de IA.
